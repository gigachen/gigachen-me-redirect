Applied machine learning

FloodCast

Monthly flood prediction for DKI Jakarta using rainfall and climate indicators.

Model
Random Forest
Validation
Chronological holdout
Result
AUC 0.724 · F1 0.687

The problem

Flood prediction depends on weather patterns that change over time, including rainfall and seasonality.

My contribution

I trained and tuned the Random Forest model, helped build the Flask app, and evaluated the model on a chronological holdout.

Approach and decisions

The team pipeline aligns monthly flood labels with rainfall and climate indicators, then compares rainfall/seasonality alone with added ENSO, IOD, or both. Random Forest hyperparameters are tuned with Optuna’s TPE search, and SHAP is used to inspect feature contributions.

The chronological 30% holdout preserves time order instead of mixing later observations into training. Lagged climate features represent delayed associations; the deployed feature list includes DMI lags from one to six months.

Evaluation and outcome

The deployed model metadata records ROC-AUC 0.7238, F1 0.6866, and accuracy 0.6557, matching the portfolio’s rounded AUC 0.724 and F1 0.687. The Flask app serves the model using the saved feature metadata.

A separate Results CSV records AUC 0.7459 for its tuned IOD experiment. That file differs from the deployment metadata; these values are reported separately rather than treating them as the same model result.

Limitations

This is an academic monthly flood-occurrence model for DKI Jakarta, not a validated emergency warning service. Chronological holdout performance does not establish accuracy in another region or across future climate conditions.

Lagged features alone do not prove an operational forecast lead time. A deployment would also need to verify which rainfall inputs are available at prediction time and evaluate prospective performance.
